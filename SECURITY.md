# Сигурност на калкулатора

Последен преглед: 08.11.2026.

## Кой какво може

| Кой | Какво |
|---|---|
| Външен човек (без вход) | Вижда само екрана за вход. Няма достъп до нито една таблица. |
| Регистрация | Само с имейл `@korekt-bg.com` и потвърждение от служебната поща. Базата отказва всички други домейни. |
| Служител (потвърден `@korekt-bg.com`) | Калкулации, оферти, каталог. Чете цените, но не може да ги сменя. Не трие. |
| Администратор (`app_metadata.role = admin` или d.mehov@korekt-bg.com) | Всичко на служителя, плюс смяна на цените, триене и управление на потребители. |
| Спрян акаунт | Губи достъп веднага, при следващата заявка, не след изтичане на сесията. |
| Гласовият асистент (публичен ключ) | Само `voice_pricing()` (цени без себестойност и ключове) и `save_voice_calc()` (само `calc:voice-…`, до 60 на час, 200 KB, редакция до 3 ч). |

## Защитни слоеве

1. **База (основната защита):** RLS в `supabase/migrations/20261108_harden_security.sql`.
   Правата се проверяват при всяка заявка срещу `auth.users` (потвърден, неспрян, служебен домейн).
2. **Регистрация:** trigger на `auth.users` отказва чужди домейни, при създаване и при смяна на имейл.
3. **Сървърни функции** (`admin-users`, `livekit-token`): проверяват токена и домейна на сървъра.
   CORS пуска само `https://dmehov-max.github.io`.
4. **Сайт:** строга Content-Security-Policy. Тръгва само кодът от сайта и вградените скриптове
   по точен хеш, а данни могат да отидат само към Supabase, Google Routes и LiveKit.
   Библиотеките са във `vendor/` с проверка SHA-256 и SRI, без чужди CDN.
   Има защита от вграждане в чужд сайт.
5. **Тайни:** в кода е само публичният `anon` ключ (той е публичен по замисъл). Адресът и ключът
   на базата не могат да се подменят от параметрите. Тестът търси изтекли тайни във всеки файл.

## Проверка

```bash
node security.test.mjs --live
```

Правата вътре в базата: постави `supabase/tests/rls_security_test.sql` в Supabase → SQL Editor → Run.
Очакван резултат е „RLS ТЕСТ: ВСИЧКО МИНАВА“. Тестът не оставя следа.

Пускай и двете след всяка промяна по входа, базата или функциите.

## Ръчни настройки (само от таблата, нямат API)

Supabase → Authentication:
- [ ] **Leaked password protection**: включи (отказва пароли, изтекли в пробиви).
- [ ] **Минимална дължина на паролата**: 12 знака, с малки, големи букви и цифри.
- [ ] **MFA (двустепенен вход)**: включи TOTP.
- [ ] **Email → Secure email change**: включено (потвърждение и на двата адреса).

Други:
- [ ] **Google Cloud → Routes API ключ:** ограничи го до HTTP referrer `https://dmehov-max.github.io/*`
      и само Routes API. Ключът е видим за влезлите колеги, затова без ограничение може да се злоупотреби.
- [ ] **GitHub и Supabase акаунтите:** двустепенен вход (2FA). Който влезе в тях, контролира всичко.
- [ ] **Netlify:** изтрий стария сайт korekt-kalkulator.netlify.app, за да не виси стара версия.
