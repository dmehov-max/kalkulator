# Калкулатор за приблизителна цена — КОРЕКТ

Пошагов калкулатор за хамалски/преместващи услуги: списък с вещи → кубатура → часове и курсове → цена.

## Живи адреси

И двата се обновяват автоматично при всеки push към `main`:

- **https://korekt-kalkulator.netlify.app/** — основен адрес (Netlify). Ако спре да се обновява с "production deployments paused" — сметката е изчерпала операционните кредити на плана; сайтът остава онлайн със старата версия, докато не се upgrade-не или изчака следващия billing цикъл.
- **https://dmehov-max.github.io/kalkulator/** — резервен адрес (GitHub Pages), включен на 2026-07-30 точно заради горния случай. Работи независимо от Netlify.

## Ценови модел накратко

Пълната логика е в `shema-na-kalkulatora.html` (визуално) и `korekt-calculator-promt.md` (текст).

- **Градско** — почасово: (пренасяне + път) × бригада × 18 €/ч, плюс същите часове × 20 €/ч транспорт. Минимум 2 часа. Разстоянието е еднопосочно.
- **Курс над 50 км** — километрично: пробег (двупосочно) × €/км, плюс труд по един от четири варианта (почасово / наши хора на ден / местен екип от база / клиентът разтоварва сам). Всяка изпратена бригада минимум 2 часа. Без минимална цена.
- **Курсове** — определят се от обема ИЛИ теглото, което свърши първо (бус 13.6 м³ / 1500 кг).
- **Стълби без асансьор** — такса на етаж: кашон, нормален уред, нестандартен уред. Едрогабаритните (диван 3-ка) се таксуват и при пътнически асансьор.
- Кубатурата определя броя курсове според вместимостта на камиона.

Пълните правила са в `korekt-calculator-promt.md`.

## Структура на кода

1. `DEFAULTS` — всички ставки и параметри
2. `CATALOG` — вещи с кубатура и тагове
3. `NEIGHBORHOODS` — квартали с координати
4. `computePrice` — ценовият двигател
5. `/* ===== END ENGINE ===== */` — под този маркер започва интерфейсът

⚠️ Не махай маркера `END ENGINE` — тестовете го ползват.

## Вход за екипа (целият калкулатор)

От 2026-08-08 **целият калкулатор е затворен зад вход** — не само Записи/
Параметри/Марж, а и самата стъпкова форма (Услуга → Локация → Вещи → Цена).
Никой без имейл+парола не вижда нищо от съветника; посетител без акаунт
попада направо на екран за вход/регистрация. Това означава, че сайтът вече
**не е публичен клиентски калкулатор** — калкулациите ги прави екипът
(на телефон с клиента или на място), не самите клиенти.

Достъпът е през истински **Supabase Auth** (имейл + парола), не UI парола в
кода. **Преди първо ползване трябва да се направи еднократна настройка в
Supabase таблото — иначе НИКОЙ, включително вие, не може да влезе:**

1. **Създай потребители.** Supabase Dashboard → Authentication → Users →
   „Add user" → имейл + парола за всеки колега, на които трябва достъп.
   (Auto Confirm User: да, за да не чакат имейл за потвърждение.)
2. **Заключи `calculations`.** Направено на 08.11.2026 с
   `supabase/migrations/20261108_lock_calculations.sql`: таблицата се чете,
   пише и трие само от `authenticated` (логнат колега); `anon` няма никакъв
   достъп. Калкулаторът праща JWT-а на сесията при всеки запис. Гласовият
   асистент пише с anon ключа само през RPC `save_voice_calc(p_id, p_status,
   p_data)`, която приема единствено id `calc:voice-...` и връща `calc_number`.

3. Готово — след push-а колегите влизат през 🔒 бутоните с имейл+парола.

**Регистрация от самите колеги (добавено 2026-08-07):** формата за вход вече
има и „Нямам акаунт — регистрация", ограничена клиентски до `@korekt-bg.com`
имейли. Реалната граница е, че Supabase изисква потвърждение на имейла, а
никой отвън няма достъп до пощата на домейна. За допълнителна защита на ниво
база (отхвърля регистрация с друг домейн директно в Postgres, дори ако някой
заобиколи клиентската проверка) — по желание, изпълни в SQL Editor:

```sql
create or replace function reject_foreign_domain_signup()
returns trigger as $$
begin
  if new.email !~* '@korekt-bg\.com$' then
    raise exception 'Регистрация само с @korekt-bg.com имейл';
  end if;
  return new;
end;
$$ language plpgsql security definer;

create trigger enforce_signup_domain
  before insert on auth.users
  for each row execute function reject_foreign_domain_signup();
```

**Известно ограничение:** таблицата `calc_params` (ценовите параметри,
включително вътрешните себестойност/марж полета) остава четима с анонимния
ключ, защото самият калкулатор я тегли при всяко зареждане, за да покаже
живите цени на клиента. Разделянето на публична/вътрешна конфигурация в
отделни таблици е следваща стъпка, ако трябва да се затвори и това.
